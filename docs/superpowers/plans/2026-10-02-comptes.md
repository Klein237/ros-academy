# Service Comptes — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un étudiant se connecte (lien par e-mail, GitHub ou Google), ouvre le lab dans la limite de son quota de minutes, fait les exercices et les QCM de son parcours, et voit sa note finale sur 20 sur une page Résultats ; quand le serveur est plein, il voit sa position dans la file d'attente.

**Architecture :** un service **Comptes** (Python, FastAPI + SQLAlchemy, Postgres) devient la seule porte d'entrée authentifiée de la plateforme :

- il ouvre une session (cookie signé, sessions en base) après une connexion par lien magique, GitHub ou Google ;
- il émet le JWT court qui ouvre le lab (`/hub/jwt_login`), seulement si le quota du mois n'est pas épuisé, avec la formule de l'étudiant ;
- il compte les minutes de lab en interrogeant l'API du Hub chaque minute, prévient 5 minutes avant la fin du quota et arrête le serveur quand il est épuisé ;
- il enregistre les tentatives de QCM (2 au plus, la meilleure est gardée), les indices utilisés et la réussite des exercices, et calcule les notes ;
- il gère une file d'attente quand le Hub est plein.

La correction des QCM, les indices et l'explication restent chez le service Contenus, mais leurs routes deviennent **internes** : Caddy les bloque depuis l'extérieur et Contenus exige un en-tête secret. Le navigateur passe par Comptes, qui applique les règles (nombre de tentatives, comptage des indices, explication après réussite).

**Tech Stack :** Python 3.12, FastAPI 0.142.2, SQLAlchemy 2.1.2, psycopg 3.3.6, Alembic 1.20.0, Postgres 16, httpx 0.28.1 (OAuth, Hub, Contenus), PyJWT 2.9.0, itsdangerous 2.2.0, email-validator 2.3.0, smtplib ; pytest (SQLite), Playwright.

**Spec :** [Plateforme de formation ROS 2 — Spec de design](https://claude.ai/code/artifact/e0a0510b-9545-459e-9c12-da51ca1898ba) — sections « Décisions clés » (comptes, évaluation, QCM), « Format d'un module, QCM et notation », « Sécurité, quotas et erreurs », sous-projet 4.

## Décisions (2026-10-02)

- **Connexion :** lien magique par e-mail, GitHub et Google. Chaque méthode s'active quand ses identifiants sont présents dans l'environnement ; sans SMTP configuré, le lien est écrit dans les journaux (développement).
- **Un compte = une adresse e-mail vérifiée.** Se connecter avec GitHub puis avec Google sous la même adresse ouvre le même compte.
- **Nom d'utilisateur Hub :** `u<id>` (stable, conforme à `^[a-z0-9][a-z0-9_-]{0,31}$`).
- **Administrateurs :** les adresses de `ADMIN_EMAILS`. `/compte/admin` échange la session contre le lien de connexion de l'éditeur (le jeton `role: admin` existant).

## Global Constraints

- Notation (spec) : module sur 20 = 50 % QCM (meilleure des 2 tentatives) + 50 % exercice (100 % sans indice, −15 % par indice, 3 au plus, 0 tant qu'il n'est pas réussi). Module terminé = exercice réussi + au moins une tentative de QCM. Note finale = moyenne pondérée par les coefficients de `parcours.yaml`, affichée quand tous les modules sont terminés.
- Quotas (spec) : formule `free` = 600 minutes de lab par mois civil, `pro` = sans limite en V1. Avertissement 5 min avant la fin ; à zéro, le serveur est arrêté et le lab refusé ; cours, QCM et notes restent accessibles.
- Session : cookie `academy_session` signé, `HttpOnly`, `Secure`, `SameSite=Lax` (retours OAuth), 30 jours, révocable (table `sessions`).
- Lien magique : usage unique, 15 min, stocké haché ; 5 demandes par adresse et par heure au plus.
- OAuth : paramètre `state` lié au navigateur (cookie signé), e-mail **vérifié** obligatoire (GitHub : e-mail principal vérifié ; Google : `email_verified`).
- Toute écriture authentifiée par cookie vérifie l'en-tête `Origin`.
- Les bonnes réponses, les indices et l'explication ne sont jamais servis par une route publique de Contenus.

## Review Focus

1. **Les règles de notation ne se contournent pas depuis le navigateur :** une 3ᵉ tentative de QCM est refusée ; les routes internes de Contenus (`POST …/qcm`, `…/indices/n`, `…/explication`) sont injoignables de l'extérieur et refusent une requête sans le secret ; l'explication n'est servie qu'après une réussite enregistrée ; un indice demandé est compté avant d'être servi.
2. **Connexion :** un lien magique ne sert qu'une fois et expire ; un `state` OAuth absent ou d'un autre navigateur est refusé ; une adresse non vérifiée chez le fournisseur est refusée ; la redirection après connexion n'accepte que des chemins locaux.
3. **Quotas :** pas de JWT de lab quand le quota est épuisé ; le serveur en cours est arrêté au passage à zéro ; une minute n'est jamais comptée deux fois (relevé idempotent par minute).
4. **Notes :** calcul exact (pénalité par indice, meilleure tentative, coefficients) ; la note finale n'apparaît que lorsque tous les modules sont terminés.

## Structure des fichiers

```
comptes/
├─ Dockerfile, requirements*.txt, alembic.ini, migrations/
├─ academy_comptes/
│  ├─ db.py           ← modèles SQLAlchemy, session
│  ├─ settings.py     ← configuration par l'environnement
│  ├─ auth.py         ← sessions, lien magique, OAuth GitHub / Google
│  ├─ mail.py         ← envoi SMTP (ou journal en développement)
│  ├─ grading.py      ← notes (fonctions pures)
│  ├─ quotas.py       ← relevé des minutes, arrêt des serveurs, file d'attente
│  ├─ clients.py      ← appels au Hub et à Contenus
│  ├─ app.py          ← pages et API
│  └─ templates/, static/
└─ tests/
contenus/      ← routes internes (secret), API des parcours, liens vers Comptes
lab-ui/        ← indices / vérification / explication via Comptes, quota, file d'attente
deploy/        ← postgres + comptes, routes Caddy
```

### Task 1 : Modèle de données et migrations

`users(id, email unique, nom, formule, cree_le)`, `identities(user_id, fournisseur, sujet unique)`, `sessions(id, user_id, cree_le, expire_le, revoquee)`, `login_tokens(hash, email, expire_le, utilise_le, suite)`, `usage(user_id, mois, minutes)` + `usage_ticks(user_id, minute)` (idempotence), `qcm_attempts(user_id, module, note, cree_le)`, `exercises(user_id, module, indices, reussi_le)`, `queue(ticket, user_id, cree_le, vu_le)`.

- [ ] Migration Alembic initiale ; tests sur SQLite.

### Task 2 : Connexion

- `/connexion` (méthodes disponibles), `POST /connexion/email`, `GET /connexion/email/<jeton>`, `/connexion/github` (+ retour), `/connexion/google` (+ retour), `POST /deconnexion`, `/compte/` (profil, quota).
- [ ] Tests : lien à usage unique, expiré, limite de demandes ; `state` invalide ; e-mail non vérifié ; fusion par adresse ; redirection locale seulement.

### Task 3 : Lab et quotas

- `GET /compte/lab?suite=/lab/…` : connecté + quota restant → JWT → `/hub/jwt_login?token=…&next=…` ; sinon connexion ou page « Quota épuisé ».
- Boucle chaque minute : serveurs prêts du Hub → +1 minute (une seule fois par minute et par étudiant) ; quota épuisé → `DELETE` du serveur.
- `GET /api/comptes/moi` : nom, formule, minutes restantes (le Lab UI avertit à 5 min).
- File d'attente : `POST /api/comptes/file` (ticket et position), battement toutes les 15 s, ticket expiré après 45 s sans battement ; le Lab UI ne retente le démarrage que lorsque son tour est arrivé (places libres ≥ position).
- [ ] Tests : JWT refusé à quota nul ; relevé idempotent ; arrêt au passage à zéro (faux Hub) ; positions et expiration des tickets.

### Task 4 : Progression et notes

- `POST /api/comptes/qcm/<module>` → 2 tentatives au plus, correction par Contenus (route interne), meilleure note gardée.
- `GET /api/comptes/exercices/<module>/indices/<n>` → compte l'indice (n ≤ utilisés + 1) puis le sert ; `POST …/reussite` ; `GET …/explication` après réussite.
- `grading.py` : note de module, module terminé, note finale pondérée.
- `/compte/resultats` : détail par module et note finale.
- [ ] Tests unitaires de `grading.py` (cas de la spec) et de l'API.

### Task 5 : Intégration

- Contenus : routes internes protégées par `X-Academy-Interne` (HMAC du secret), `GET /api/contenus/parcours/<id>`, boutons « Ouvrir le lab » → `/compte/lab?suite=…`, QCM du site → Comptes (tentatives restantes, invitation à se connecter).
- Lab UI : indices, vérification et explication via Comptes ; bandeau quota ; position dans la file ; écran « Session expirée » → « Se reconnecter » (`/compte/lab?suite=<page>`).
- Caddy : `/connexion*`, `/deconnexion`, `/compte*`, `/api/comptes/*` → comptes ; `respond 404` sur les routes internes de Contenus.
- Compose : `postgres` (volume), `comptes` ; `.env.example` (SMTP, OAuth, `ADMIN_EMAILS`, `DATABASE_URL`).
- [ ] e2e : connexion par lien magique (lien lu dans les journaux), lab ouvert, exercice + indice + QCM, page Résultats ; quota épuisé ; 3ᵉ tentative refusée ; route interne bloquée.
