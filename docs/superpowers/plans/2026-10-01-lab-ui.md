# Lab UI — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un étudiant connecté par le lien du site arrive sur `/lab/`, attend son conteneur sur un écran d'attente, puis fait tout le module Nœud dans le navigateur : terminaux ROS, éditeur de fichiers, vue 2D du robot, reconnexion automatique, arrêt après 20 min d'inactivité avec avertissement 5 min avant.

**Architecture :** une application web statique (Vite + TypeScript, sans framework) servie par Caddy sous `/lab/`, sur la même origine que le Hub. Après `/hub/jwt_login`, la page demande au Hub un jeton API court, limité au serveur de l'étudiant (`GET /hub/lab_token`, ajouté à `rosacademy_hub`). Ce jeton sert à tout : API du Hub (démarrage, progression, arrêt), API fichiers et terminaux de jupyter-server, WebSocket du terminal et de rosbridge (paramètre `?token=`, seul moyen pour un WebSocket de navigateur). Un petit simulateur de robot différentiel sans interface (`academy-diffbot`) est ajouté à l'image `ros-lab` pour que la vue 2D ait quelque chose à montrer.

**Tech Stack :** Vite 8.3.2, TypeScript 5.9.3, @xterm/xterm 6.0.0 + @xterm/addon-fit 0.11.0, monaco-editor 0.57.0, canvas 2D, protocole rosbridge v2 (client maison, sans roslibjs), Vitest 5.0.3 + jsdom 30.1.1, Playwright 1.56.1, Caddy 2.8, JupyterHub 5.2.1.

**Spec :** [Plateforme de formation ROS 2 — Spec de design](https://claude.ai/code/artifact/e0a0510b-9545-459e-9c12-da51ca1898ba) — sections « Architecture d'ensemble », « Déroulé d'une session de lab », « Sécurité, quotas et erreurs », sous-projet 2.

## Global Constraints

- Même origine que le Hub (`https://<domaine>/lab/`) : pas de CORS, cookies du Hub utilisables par `/hub/lab_token`.
- Le jeton du navigateur est limité à l'étudiant (`access:servers!user=<nom>`, `servers!user=<nom>`), expire en 1 h, n'est jamais écrit dans `localStorage` ni dans l'URL de la page.
- Le JWT de connexion n'est jamais recopié dans l'URL de redirection après `/hub/jwt_login`.
- CSP stricte sur `/lab/` : scripts de la même origine uniquement, pas d'`eval`.
- Le Lab UI n'interroge jamais le conteneur en tâche de fond (sinon le serveur ne serait jamais vu inactif) ; seul le Hub est interrogé périodiquement.
- Inactivité : avertissement après 15 min sans interaction, arrêt du serveur par le Lab UI à 20 min. Le culler du Hub (sous-projet 1) reste le filet de sécurité quand l'onglet est fermé.
- Monaco est chargé à la demande : le terminal doit être utilisable avant que l'éditeur soit téléchargé.
- Interface en français.

**Écart assumé par rapport à la spec :** la position dans la file d'attente n'est pas affichée. Le Hub renvoie seulement 429 quand il est plein ; une vraie file avec position demande un état partagé entre étudiants, qui sera porté par le service Comptes (sous-projet 4). En attendant, le Lab UI affiche « Serveur plein » et réessaie automatiquement toutes les 15 s.

**Découvert pendant l'implémentation :** Chromium n'envoie pas `Sec-Fetch-Mode: websocket` lors de la poignée de main ; JupyterHub ignore alors le `?token=` des WebSockets. Le Hub active donc `JUPYTERHUB_ALLOW_TOKEN_IN_URL=1` dans les conteneurs, et Caddy pose `Content-Security-Policy: sandbox` sur tout `/user/*` : une page servie par le conteneur d'un étudiant (fichier HTML, jupyter-server-proxy) partage sinon l'origine du Lab UI et pourrait lire `/hub/lab_token` avec le cookie d'un autre étudiant. Test : Task 1 (`test_student_served_pages_are_sandboxed`).

**Hors de ce plan :** copie de `lab/` du module, boutons Commencer l'exercice / Vérifier / Réinitialiser (format des modules, sous-projet 3) ; quota de minutes par mois (sous-projet 4).

## Review Focus

1. **Le jeton du navigateur ne donne accès qu'au serveur de l'étudiant.** Le jeton d'Alice est refusé sur `/user/bob/…` et sur l'API d'administration. Test : Task 1 (`test_lab_token_is_scoped_to_its_owner`).
2. **`/hub/lab_token` n'est pas exploitable depuis un autre site ni depuis une page d'étudiant** : sans cookie → 403 ; `Sec-Fetch-Site: cross-site` → 403 ; un jeton du Lab UI ne permet pas d'en obtenir un autre ; les pages sous `/user/*` sont en CSP `sandbox`. Tests : Task 1 (`test_lab_token_requires_same_site_cookie`, `test_student_served_pages_are_sandboxed`).
3. **Coupure réseau** → le terminal se reconnecte au même terminal (l'historique du shell est conservé). Test : Task 7 (`reconnexion`).
4. **Conteneur arrêté pendant la session** (culler, plantage) → message clair + bouton Relancer, fichiers conservés. Test : Task 7 (`serveur arrêté`).
5. **Fichier modifié non enregistré** → signalé dans l'onglet et à la fermeture de la page ; un fichier binaire ou trop gros n'est pas ouvert en texte. Tests : Task 4 (unitaires).
6. **Serveur plein (429)** → écran « Serveur plein », nouvel essai automatique, pas d'erreur générique. Test : Task 2 (unitaire) et Task 7 (`serveur plein`).

### Task 1 : Jeton du navigateur (`/hub/lab_token`) et redirection après connexion

**Files:** Modify `hub/rosacademy_hub/auth.py`, `hub/jupyterhub_config.py`, `hub/tests/test_auth.py`, `tests/integration/test_session.py`.

**Interfaces :**
- `GET /hub/lab_token` (cookie du Hub) → `200 {"user": str, "token": str, "expires_in": 3600, "server_url": "/user/<nom>/"}`, `Cache-Control: no-store`.
- Scopes du jeton : `access:servers!user=<nom>`, `servers!user=<nom>`, `read:users:name!user=<nom>`.
- `lab_token_scopes(name) -> list[str]`, `is_cross_site(headers) -> bool` (fonctions pures, testées seules).
- `/hub/jwt_login` sans `next` → redirection vers `/lab/` (et non plus `/hub/spawn?token=<JWT>`).

- [ ] Tests unitaires : scopes exacts ; `Sec-Fetch-Site` absent / `same-origin` / `none` acceptés, `cross-site` / `same-site` refusés.
- [ ] Tests d'intégration : `test_lab_token_is_scoped_to_its_owner`, `test_lab_token_requires_same_site_cookie`, `test_login_redirects_to_lab_without_jwt`.
- [ ] Commit `feat(hub): scoped browser token for the lab UI`.

### Task 2 : Socle du Lab UI, Hub et écran d'attente

**Files:** `lab-ui/package.json`, `tsconfig.json`, `vite.config.ts`, `index.html`, `src/config.ts`, `src/backoff.ts`, `src/api/hub.ts`, `src/session.ts`, `src/ui/waiting.ts`, tests associés.

**Interfaces :**
- `HubClient.labToken()`, `.server()`, `.start() -> "started" | "pending" | "running" | "full"`, `.progress(onEvent)`, `.stop()`.
- `parseSSE(chunk, buffer) -> {events, rest}` pour lire `/server/progress` avec `fetch` (EventSource ne permet pas d'en-tête `Authorization`).
- `Session` : états `auth → starting → ready`, `full` (réessai 15 s), `failed`, `stopped`, `noauth`.
- [ ] Tests : 429 → `full` puis nouvel essai ; progression `failed` → `failed` avec message ; jeton 403 → `noauth`.

### Task 3 : Terminaux (xterm.js) avec reconnexion

**Files:** `src/api/terminals.ts`, `src/ui/terminals.ts`.

- WebSocket `wss://…/user/<nom>/terminals/websocket/<id>?token=…`, messages `["stdin", …]`, `["set_size", rows, cols]`, `["stdout", …]`.
- Fermeture inattendue → reconnexion avec délai croissant (0,5 s → 10 s) au **même** terminal ; terminal disparu (404) → nouveau terminal ; serveur arrêté → l'écran passe à `stopped`.
- Onglets : plusieurs terminaux (un pour `ros2 run`, un pour `ros2 topic echo`).
- [ ] Tests : `Backoff`, reconnexion au même nom, bascule vers un nouveau terminal sur 404.

### Task 4 : Fichiers et éditeur (Monaco chargé à la demande)

**Files:** `src/api/contents.ts`, `src/paths.ts`, `src/lang.ts`, `src/ui/files.ts`, `src/ui/editor.ts`.

- Arborescence paresseuse de `/home/etudiant`, nouveau fichier / dossier, suppression, onglets, `Ctrl+S`, pastille « non enregistré », alerte `beforeunload`.
- Langage selon l'extension (`.py`, `.cpp`, `.hpp`, `CMakeLists.txt`, `package.xml`, `.launch.py`, `.yaml`, `.urdf`, `.xacro`, `.sh`, `.md`).
- Fichiers > 1 Mo ou binaires (`format: base64`) : non ouverts, message.
- Paramètre `?open=<chemin>` : ouvre ce fichier au démarrage (utilisé par « Ouvrir dans le lab » du site, sous-projet 3) ; `?dossier=<chemin>` : dossier de départ de l'arborescence et des terminaux.
- [ ] Tests : `joinPath` / `parentOf` refusent `..` ; `languageFor` ; modèle de document (dirty / save).

### Task 5 : Vue 2D (rosbridge) et simulateur `academy-diffbot`

**Files:** `src/ros/rosbridge.ts`, `src/ros/pose.ts`, `src/ui/view2d.ts`, `images/ros-lab/academy_diffbot.py`, `images/ros-lab/Dockerfile`, `tests/image/test_image.sh`.

- Client rosbridge : `subscribe(topic, type, cb, throttle_rate)`, `advertise/publish`, `callService` (réponse par `id`), réabonnement après reconnexion.
- Vue : grille 1 m, robot orienté, trace, sujet de pose réglable (`/odom`, `nav_msgs/msg/Odometry`), pavé de téléopération (`/cmd_vel`, `geometry_msgs/msg/Twist`), liste des topics (`/rosapi/topics`).
- `academy-diffbot` : s'abonne à `/cmd_vel`, intègre la cinématique différentielle à 20 Hz, publie `/odom`. Arrêt du robot si aucune commande depuis 0,5 s.
- [ ] Tests : quaternion → lacet ; formats des messages rosbridge ; réabonnement ; `test_image.sh` : `/odom` avance après un `/cmd_vel`.

### Task 6 : Inactivité, avertissement et arrêt

**Files:** `src/idle.ts`, `src/ui/banner.ts`.

- Activité = clavier, souris, molette, toucher dans la page (et message `rosacademy:activity` d'une page parente de même origine, si le site intègre le lab dans un iframe).
- 15 min → bandeau « Le lab s'arrêtera dans 5 min » + bouton « Je suis là » ; 20 min → `DELETE /hub/api/users/<nom>/server`, WebSockets fermés, écran « Lab arrêté pour inactivité, vos fichiers sont conservés » + Relancer.
- `?inactivite=<secondes>` ne peut que **raccourcir** le délai (tests de bout en bout).
- [ ] Tests (minuteries simulées) : avertissement, remise à zéro par une activité, arrêt.

### Task 7 : Déploiement et tests de bout en bout

**Files:** `lab-ui/Dockerfile`, `deploy/Caddyfile`, `deploy/docker-compose.yml`, `deploy/README.md`, `lab-ui/playwright.config.ts`, `lab-ui/tests/e2e/lab.spec.ts`, `.github/workflows/ci.yml`.

- Caddy construit depuis `lab-ui/Dockerfile` (Node → `dist/` → `caddy:2.8`) : aucun Node sur le serveur.
- `/lab/*` : fichiers statiques, `index.html` non mis en cache, assets `immutable`, en-têtes CSP / `X-Content-Type-Options` / `Referrer-Policy`.
- Scénarios Playwright : écran d'attente puis terminal ; module Nœud complet (paquet Python, nœud écrit dans l'éditeur, `colcon build`, `ros2 run`, `ros2 topic echo` dans un 2ᵉ terminal) ; vue 2D qui bouge avec la téléopération ; reconnexion après coupure réseau ; serveur arrêté → Relancer ; lien invalide → « Rouvrez le lab depuis le site » ; inactivité raccourcie → arrêt ; serveur plein.
- [ ] CI : job `lab-ui` (typecheck, Vitest, build) ; e2e dans `integration`.
